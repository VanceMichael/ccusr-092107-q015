# 运河双线巡航闭环

把电子巡查组的智慧感知结论与水上巡查组的现场登临核验串成**同一条处置闭环**：

```
智慧感知发现 → 远程核验 → 预警推送 → 船舶叫应
   → 巡查艇任务 → 登临检查 → 复查 → 闭环
（登临前任意阶段可"误报撤销"，撤销后自动通知并撤任务、放泊位）
```

## 解决的核心问题

- **两个系统船舶标识不同**：雷达批号、视频 OCR 船名、AIS MMSI、登记船名
  通过"规则打分 + 并查集"归并为同一身份簇；登记库绑定 100 分、
  牌证识别 80 分、时空邻近约 60 分，**每一条关联都保留规则、分值与
  数据依据**，可在 `explain()` 中逐条复核。一个匿名批号同时邻近两艘
  登记船舶时挂起为"身份待判定"，禁止派艇，由值班员人工确认/否认锁定。
- **传感器迟到补报**：事件区分 `at`（发生时间）与 `recv`（到达时间）。
  断网补传的依据照收并打"迟到"标、归入证据链，但**不新建重复风险、
  不回退阶段、不改写人工结论**；已闭环/已撤销的风险也不会被迟到数据复活。
- **人员/巡查艇/泊位时空冲突**：派艇时一次校验艇与人员的时间重叠、
  跨航段 ETA 可达性、锚地泊位占用；冲突即拒绝并给出建议时间/空闲泊位。
  复查默认复用登临原班人马，冲突时按 15 分钟档自动顺延。
- **值班员视图与反查**：`board()` 列出所有未闭环风险（含身份待判定、
  在办任务、泊位占用）；`lineage(risk_id)` 可从现场复查结论一路反查
  到最初的雷达点迹、视频抓拍、水文读数及其设备与原始报文。

## 代码结构

| 模块 | 职责 |
| --- | --- |
| `src/model.py` | 风险聚合、七阶段状态机、终态/撤销、人工锁定、依据与时间线 |
| `src/identity.py` | 多源身份归并（并查集 + 可解释规则链 + 人工判定锁定） |
| `src/engine.py` | 事件摄入、关联去重、七阶段指令、迟到数据规则、值班台与反查 |
| `src/dispatch.py` | 巡查艇/人员排班、ETA 可达性、锚地泊位冲突、复查顺延 |
| `src/replay.py` | 剧本回放：按序喂事件与指令，自动核对终态期望 |
| `src/context.py` | 领域资料与运河基础资料的读取、引用完整性校验 |
| `fixtures/canal.json` | 平陆运河样例航段、设备、登记库、艇组人员、锚地泊位（全虚构） |
| `fixtures/events.json` | 样例处置剧本，覆盖各类正常与异常路径（见下） |

## 样例剧本覆盖

`fixtures/events.json` 是 2026-09-30 的一日巡航剧本，包含：

1. 低水位风险：水文触发 → 叫应当场自改闭环；水位站断网补传不改变结论；
2. 违规锚泊：雷达+视频+AIS 三源归并 → 无应答派艇 → 登临查实 →
   雷达/PDA 断网批次补传 → 复查通过闭环；
3. 雷达误报：远程核验撤销，迟到的补报点迹不能复活警情；
4. 身份歧义：雷达批号同时邻近两艘登记船，派艇被拦截；人工确认后
   两条警情合并、重复派艇任务自动撤销；
5. 人工否认：迟到强证据不能翻案；
6. 泊位冲突：指定占用泊位被拒，空闲泊位自动分配；
7. 气象预警推送后保持"未闭环"，值班台可见。

## 快速校验

```bash
python -m unittest discover -s tests
```

回放样例剧本并查看终态核对与值班台：

```python
from src.replay import Replay

r = Replay.from_files("fixtures/canal.json", "fixtures/events.json")
result = r.run()
assert result["passed"]                     # 全部终态期望通过
print(result["board"]["unclosed_count"])    # 值班员视角的未闭环风险
for risk_id in ...:
    print(r.engine.lineage(risk_id))        # 现场结论 → 最初雷达/视频/水文依据
```

所有船名、人员、编号、轨迹均为虚构样例，不含账号、凭据或真实主体信息。
